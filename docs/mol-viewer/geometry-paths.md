# 连续路径检查与扭曲环带区域

这是复杂扭曲骨架基础能力的第二批，演示入口 `/?demo=geometry-paths`。分子连接关系、环带区域、目标几何和检查报告分别表达，通过稳定原子 ID 关联；没有新增 npm 包，也没有使用真实分子的现成坐标。

## 线性路径检查

`@retainmol/mol-viewer/geometry` 与 `/headless` 导出 `validateGeometryMotion(before, after, options)`。两份分子的原子、键和连接关系必须一致。它检查每个原子沿 `p(t) = (1 - t) * before + t * after` 移动的完整区间，`t` 从 0 到 1。

检查三类几何间距：原子—原子、原子—键段、键段—键段。默认分别为 0.8、0.15、0.1 Å。原子对排除图距离不超过两键的邻居；原子—键排除端点及与端点直接相连的原子；键对排除共享端点。它们是明确的骨架几何下界，不是元素相关的范德华半径。

邻域排除不允许键长压塌，或两键以内的近邻接近重合；这些情况另有解析最小距离退化检查，阈值为 1e-6 Å 与浮点裕量的较大值。但这仍不是连续键角、手性、局部体积或完整分子表面的证明。起点和终点之间如果需要刚体旋转，应检查实际旋转路径，不能用线性插值替代。

起点、终点都安全，不能替代整个路径安全。实现通过区间上的距离下界和速度界排除碰撞，并在必要时细分区间；不是只检查固定数量的动画帧。保守推进作为连续碰撞检测的基础方法可参见 [C-IPC 原始研究](https://ipc-sim.github.io/C-IPC/)。本项目实现为有界浮点几何检查，并未集成该论文的动力学、能量或力学求解器。

返回值区分：

- `safe`：本次线性路径通过指定间距及拓扑排除规则下的检查。
- `collision`：找到不满足间距的时刻，报告涉及原子、键、时间和距离。
- `indeterminate`：预算或数值分辨能力不足；不能作为允许应用的依据。
- `invalid-input`：输入、连接关系或选项无效。

`maxDepth` 控制细分深度，`maxChecks` 同时限制候选对访问和距离计算；耗尽预算不会返回 `safe`。报告中的 `timeInterval` 和 `sampleTime` 用于定位诊断，不保证报告第一处接触的精确时刻。

整段轨迹的扫掠包围盒先排除相距很远的基元，近处再进行距离下界和区间细分检查。坐标绝对值上限为 1e9 Å，每份输入最多 10000 个原子和 10000 条键；更小的实际工作量也可能耗尽预算，此时必须处理 `indeterminate`。

## 接入现有事务

```ts
const preview = previewConstrainedGeometry(context, {
  targetObjectId,
  request: {
    movableAtomIds,
    constraints,
    motion: {}, // 明确启用完整线性路径检查，使用默认间距及预算。
  },
})
```

`motion` 是可选项，旧请求仍保留原有终点校验行为。启用后，初态与最终候选之间的线性路径必须通过，才能得到可应用预览。提交时重新求解和检查，仍受 revision 与整批事务保护。

失败保留原分子；`motionReport` 描述被检查或拒绝的轨迹，不能解释为已经应用了目标坐标。`report` 仍是返回分子的终点约束报告；求解器可另附 `attemptReport` 描述被拒绝的候选。数值求解器的内部迭代不等于这条显示路径。

当前只检查明确的一段线性插值。它不会自动寻找绕行路线，也不保证宿主采用其他动画插值、旋转轨迹或直接拖动时同样安全；这些路径必须分别检查。初始碰撞不会被静默忽略。

## 环带区域与程序初态

`GeometryRibbonRegion` 显式列出按顺序排列的截面，每个截面用 `leftAtomId`、`rightAtomId` 指向已有原子。相邻截面的两条纵向连接必须存在，但横截面不要求是化学键。闭合方式单独表示：

- `open`：不要求首尾闭合。
- `parallel`：末左接首左，末右接首右。
- `crossed`：末左接首右，末右接首左。

`validateRibbonRegion` 检查 ID、截面与连接关系。`measureRibbonGeometry` 提供截面宽度和相邻截面经切向平行运输后的局部扭转角；接缝也参与测量。它不自动猜测区域，不分配化学 P/M，也不证明整个分子的莫比乌斯拓扑。

`createRibbonGuide` 根据截面数、半径、半宽和带符号的半扭转次数生成解析环形带目标。奇数半扭对应 `crossed` 接缝，偶数对应 `parallel`。Demo 展示零、一、三半扭及镜像方向；这些点只是程序生成的几何骨架，不代表论文分子、合理键长或低能构象。

`compileRibbonGuideConstraints` 将 guide 按 region 的稳定 ID 编译为已有 `position` 软约束。它不修改分子、不创建连接，也不直接提交画布。真实骨架仍需通过原有局部求解、手性和路径检查；过大的几何变化可能不收敛。

`/headless` 另提供 `geometryMotionOptionsSchema`、`geometryRibbonRegionSchema`、`geometryRibbonGuideRequestSchema`，供 API 接收 JSON 时做格式和预算边界检查。区域连接关系仍由对应的纯几何校验器检查。

## 验证状态

2026-09-22：根 `npm run verify` 全通过，包含严格类型、边界、1482 项 Vitest 测试、生产构建、20 个入口的 API 报告、打包与独立消费端检查。本批新增 105 项测试：运动检查 33、求解器集成 12、环带区域与 guide 45、公共事务/schema 6、应用演示 9。

Edge 实操验证：穿越场景初态与目标的键段分离，中途 `t = 0.5` 间距为 0，报告碰撞且禁用应用；点击诊断会定位并高亮右侧对应时刻的两个键段。原结构始终保持 z = 1。安全场景应用后 z = 2，一次撤销恢复 z = 1，重做恢复 z = 2。名义目标与被拒绝的求解候选报告分开，右侧轨迹和所显示的诊断保持一致。

环带 WebGL 视图、镜像切换、零扭转及接缝截面定位已实操。24 截面的三半扭样例局部扭转均约 22.5°，镜像为 −22.5°；零扭转测得 0°，接缝切换为同侧闭合。

独立合成审查额外覆盖非中点短暂穿越、近平行、大坐标及预算不足：96 组已知交叉得到 55 次碰撞、41 次无法确认安全，没有放行；这不是一般正确性的形式化证明。100 原子/120 条键的合成格网轻微移动在默认预算内通过。四面体星图的 180° 目标端点合法、但线性中途近邻压塌的反例已转为公共回归测试并拒绝应用。
