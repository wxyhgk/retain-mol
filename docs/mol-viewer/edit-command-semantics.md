# 编辑命令的一致性

编辑使用同一个分子状态与命令内核。`/runtime` 的实例编辑 API、viewer 操作和 `/headless` 回放共用命令；`/modeling` 负责把已完成的计划结果作为一次事务提交。
本轮不新增 npm 包或公开 API，也不改变 Molecule / JSON schema。

## 无变化操作与历史

- 命令的 `changed` 表示分子数据实际改变，不以“创建了新对象”作为依据。
- `lib/model/equality.ts` 比较完整数据：ID、数组顺序、坐标、同位素、标签、立体标记和嵌套配位字段都参与。对象字段的书写顺序和缺省可选字段不影响判定；不使用哈希判断相等。
- 普通坐标写入采用精确比较；微小但真实的坐标变化仍算编辑。键长/键角目标与当前测量值相差不超过 `1e-10` 时忽略浮点误差；二面角按 360° 周期比较。居中时质心各分量不超过 `1e-10 Å` 也直接返回。
- 已经相同的键长/角度、坐标、中心位置或推断键结果不增加撤销记录。重复导入完全相同的分子不清空选择；重复清空空分子可以清空选择，但不增加分子历史。
- 计划中的操作即使分别产生变化，最终数据回到原值时仍返回 `changed: false`，`nextRevision` 保持基准版本；viewer 不提交，不破坏 redo。
- 连续编辑会话回到起点后正常结束，同样不留下多余历史。历史比较还包含对象名称、显示/锁定状态、偏移和对象顺序，不能把真实场景修改当作无变化。

这里的“相同”是带 ID 的数据相同，不是化学结构同构；删除后重新创建实体可能产生新 ID，属于数据变化。

## 手性收尾

`commands/shared/commandResult.ts` 只包装结果。
`commands/shared/moleculeEdit.ts` 的 `editMolecule(previous, candidate)` 负责已知前后分子的编辑收尾：先排除无变化，再协调已指定的 R/S，最后检查是否仍有实际变化。

- 改元素、键或坐标后，已有 R/S 按当前连接和几何重新感知；失去可识别手性时移除旧标记及属于该中心的楔形键。
- 没有指定 R/S 的中心不会因普通编辑而自动获得标记。
- 无变化命令不顺便修复旧标记。外部整分子加载仍执行原有的手性协调；字段保真与输入校验边界见[基础字段与保真边界](./field-fidelity.md)。
- 几何命令现在也走同一收尾；计划中的旋转通过公共坐标命令落地。计划执行器和 runtime 提交不再各自额外执行一次全分子手性协调。
- 底层替换元素/显式立体操作保留原有收尾，以兼容其既有直接调用者；这次没有替换手性感知算法，也没有新增 E/Z 感知体系。

## 稳定 ID

- 修改已有原子或键时，仍存在的实体保留 ID。元素替换保留该原子的 ID、坐标和连接，按原规则移除不再适用的元素同位素/配位配置；其他原子的同位素和标签保留。
- 自动推断键按无序端点对匹配已有键，保留仍存在的键 ID、端点方向和顺序；键级不变时保留其元数据。只有新增端点对生成新 ID。
- 推断导致键级改变时，保留 ID，但清除原有的芳香性、楔形和 E/Z 标记，避免沿用旧键级的注记。
- 不保证被删除实体重新出现时复用旧 ID；新建/粘贴/导入冲突处理继续沿用原有 ID 分配与重映射规则。

推断键的无变化保护已放进纯命令，store 不再维护一份忽略 ID 的拓扑比较补丁。
