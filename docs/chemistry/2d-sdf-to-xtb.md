# 从第一性原理理解：为什么 2D SDF 不能直接丢给 xTB

本文解释 RetainMol 中“补 H + 生成 3D”按钮的必要性。核心结论是：

```text
2D SDF 是化学结构图，不是可直接计算的三维分子几何。
```

xTB 需要的是“所有原子的三维坐标”。ChemDraw/Chem3D 风格的 2D SDF 通常只提供重原子骨架、二维坐标和键连接。如果直接把这种数据交给 xTB，计算对象本身就不完整。

## 1. 分子计算到底需要什么

量子化学或半经验方法的输入不是“分子名称”，也不是“二维结构式”，而是一组原子核：

```text
元素类型：C / H / N / O / ...
三维坐标：x, y, z
总电荷
自旋多重度
```

xTB 根据这些原子核的位置和电子数求解近似电子结构，然后沿能量梯度移动原子，寻找局部能量最低点。

所以，对 xTB 来说：

```text
少一个 H = 换了一个分子
所有 z=0 = 给了一个高度受限且通常很差的初始构型
键级/芳香性丢失 = 化学价态解释可能错误
```

## 2. 2D SDF 实际包含什么

以 `data/test.sdf` 为例：

```text
71 个原子
0 个 H
所有 z 坐标都是 0
来源是 ChemDraw 2D V2000
```

这类文件适合表达“结构图”：

```text
哪些重原子相连
大致拓扑关系
绘图用二维布局
```

但它不适合直接表达“真实三维构象”：

```text
C-H 原子没有显式列出
芳香环、共轭体系、隐式氢需要化学感知推断
二面角完全缺失
空间位阻关系不真实
```

## 3. 为什么缺 H 会让 xTB 失败

氢不是装饰，它直接决定分子：

```text
原子数
电子数
价态
局部杂化
电荷分布
几何优化路径
```

例如一个芳香碳在结构图中看起来只连着两个碳，但它实际还连着一个 H。2D SDF 可以把这个 H 作为“隐式氢”省略；xTB 不能自动从结构图里补出来，它只计算输入文件里明确出现的原子。

因此，直接把缺 H 的结构交给 xTB，相当于让 xTB 计算一个化学上不同甚至不合理的体系。常见表现是：

```text
SCF 不收敛
几何优化失败
键长/键角走向异常
最终结构不可信
```

## 4. 为什么所有 z=0 也有问题

2D 坐标是绘图坐标，不是分子构象。所有原子都在一个平面时：

```text
本应扭转的单键没有二面角
侧链互相重叠或距离过近
非键相互作用很差
初始梯度可能很大
```

xTB 是优化器，不是专门的 2D 到 3D 构象生成器。它擅长从一个“基本合理的 3D 初始结构”继续下降到局部最低点，而不是从二维结构图推断完整三维构象空间。

## 5. Chem3D 为什么看起来更好

Chem3D 通常不会直接把 2D SDF 丢给半经验/量化优化。它会先做结构准备：

```text
识别隐式氢
补显式 H
生成 3D 构象
用 MM2/MMFF/UFF 等力场快速预优化
再交给更高层级方法优化
```

也就是说，Chem3D 好用的关键不是“优化器更神奇”，而是它在优化前做了化学感知的结构清理。

## 6. RetainMol 当前的处理流程

RetainMol 增加了显式的结构准备步骤：

```text
当前 Molecule
→ 导出 MOL
→ 后端 /prepare/3d
→ OpenBabel: -h --gen3d --best
→ 返回 3D MOL
→ 前端替换当前结构
→ 再运行 xTB
```

对应命令等价于：

```bash
obabel input.sdf -O prepared.mol -h --gen3d --best
```

参数含义：

```text
-h       根据价态和键级补显式 H
--gen3d  从 2D 拓扑生成三维坐标
--best   使用更稳的构象生成/力场处理策略
```

在 `data/test.sdf` 上，结构准备后得到：

```text
109 个原子
38 个 H
非零 z 坐标
```

随后再用 xTB GFN-FF 优化可以正常结束。

## 7. 推荐计算工作流

对于 2D SDF / ChemDraw MOL，推荐：

```text
1. 导入 2D SDF
2. 点击“补 H + 生成 3D”
3. 检查结构是否合理
4. 先用 xTB GFN-FF / loose 做预优化
5. 再用 xTB GFN2 做更精细优化
```

不要把步骤 2 隐藏在 xTB 按钮里。原因是补 H 和生成 3D 会改变结构，应该由用户显式确认。

## 8. 工程边界

前端负责：

```text
展示结构
编辑原子/键
提示 2D 或缺 H
显式触发结构准备
```

后端负责：

```text
调用 OpenBabel / 未来可替换为 RDKit
补 H
生成 3D
预优化
调用 xTB
流式返回优化轨迹
```

这条边界比在前端手写复杂化学规则更可靠。芳香性、隐式氢、构象生成和力场预优化都属于化学工具链擅长的工作。
